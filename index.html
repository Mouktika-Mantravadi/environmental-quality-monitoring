ESP32 & Cloud Integration Roadmap

1. Current Status: Synthetic Testbed Mode

The dashboard is currently running in a zero-dependency local simulation mode. All data values (Temperature in °C, Humidity in %, and Gas Sensor in Raw ADC values) are synthetically generated so you can evaluate the user interface, line charts, thresholds, and alarm logs without needing the physical microcontroller or Mokxi setup online.

2. Expected Telemetry Payload Specification

When your ESP32 simulation in Mokxi/Wokwi or physical ESP32 board is ready, configure it to publish JSON payloads in the following format:

{ "device_id": "ESP32_ENV_NODE_01", "temperature": 26.4, // °C (from DHT22 or BME280) "humidity": 54.2, // % Relative Humidity "gas_raw": 680, // 12-bit ADC raw integer (0-4095) from MQ-135/MQ-2 "wifi_rssi": -65, // dBm "timestamp": 1728918230 // Unix epoch seconds }

3. Communication Protocols

You can transmit this payload via:

  • MQTT over WebSockets: Connect directly to HiveMQ Cloud, Adafruit IO, or EMQX broker.
  • HTTP REST / Webhook: Use ESP32 HTTPClient library to POST readings to a cloud endpoint (e.g. Firebase, ThingSpeak, or a lightweight Node.js/Python server).
  • ESP32 Local Web Server: Host the dashboard directly on the ESP32 SPIFFS/LittleFS or serve SSE (Server-Sent Events) on the local Wi-Fi IP address.
